01 · SCOPE & DOMAIN

功能范围与领域模型

测试套是用户管理的核心对象；Token 提供受控认证；执行机承载实际 HTTP 请求；调度器与 Kafka 将配置流量转换为可弹性消费的执行流量。

01

测试套管理

管理同一应用、同一环境下的一组 HTTP 用例、调度策略、断言和探测点选择。

02

Token 管理

维护测试套访问目标服务所需的认证凭据引用，支持轮换、吊销和审计。

03

执行机管理

维护探测 Worker 的注册、心跳、标签、容量、排空和故障隔离状态。

角色与权限

  • Viewer：查看测试套、执行记录和执行机健康。
  • App Owner：维护所属应用测试套，绑定已授权 Token。
  • SRE：发布/暂停任务，管理执行机和容量策略。
  • Security Admin：审批生产 Token、轮换与吊销。
  • Platform Admin：平台配置和紧急停机，不可读取 Token 明文。

边界与非目标

  • 仅支持 HTTP/HTTPS，不提供独立 TCP、DNS、gRPC 拨测。
  • POST 仅允许已标记为无副作用的健康检查接口。
  • 测试套不是压测脚本，不允许用户配置任意并发。
  • 执行机不允许直接编辑 Pod IP；实例由 K8S 控制器管理。
  • Token 不在页面、日志、Kafka 消息和执行结果中回显。

03 · PROBE TOKEN

拨测 Token 管理

Token 是目标应用认证凭据的逻辑句柄。平台控制面只保存元数据和密文引用，Worker 在执行时凭工作负载身份获取短期可用值。

01创建

用户输入一次；HTTPS 传输；字段校验；不进入前端日志。

02加密托管

Vault/KMS 信封加密；数据库只保存 secretRef 与版本。

03绑定

限定 appId、environmentId、域名、Header 和有效期。

04运行时获取

Worker ServiceAccount 换取短期授权，内存中注入。

05销毁

请求结束清理引用；日志和 Result 统一脱敏。

Token 字段与状态

  • 字段：tokenId、name、type、appId、environmentId、secretRef、version、expiresAt、lastUsedAt、owner。
  • 类型：Bearer、API Key、Basic（受控）；不支持用户脚本动态签名。
  • 状态：ACTIVE → ROTATING → ACTIVE；ACTIVE → REVOKED；过期自动 EXPIRED。
  • 展示：创建成功仅展示一次确认，不提供“查看明文”；列表显示掩码与后 4 位指纹。

轮换与吊销

  • 轮换：创建新 version，旧/新版本允许 5–30 分钟重叠；新任务使用新版本，旧在途请求完成后失效。
  • 吊销：立即禁止新获取，发布 TokenRevoked 事件；关联测试套标记 NEEDS_TOKEN。
  • 过期：提前 30/7/1 天通知；过期后任务不发送，避免制造 401 告警风暴。
  • 审计：记录创建、绑定、轮换、吊销和使用主体，不记录 Token 值。
威胁控制措施验收证据
明文泄漏只写不读、KMS/Vault、TLS、日志脱敏、响应 Header/Body 截断。代码扫描无 Token；日志注入测试无明文。
越权使用Token 绑定应用+环境+域名；Worker 身份和 Topic ACL 双重校验。跨应用、跨环境、跨域名均返回 403。
缓存残留Worker 内存 TTL ≤ 5 分钟；不写磁盘；Pod 终止清理；禁用 Core Dump。Pod 重启与内存检查无可恢复明文。
轮换中断双版本重叠、灰度验证、失败自动回滚到旧版本（未吊销前）。轮换演练期间成功率不低于基线。

功能规则异常处理
自动注册Pod 启动使用 ServiceAccount 注册 instanceId、pool、zone、version、capacity、capabilities；禁止自报环境越权。身份或标签不匹配进入 QUARANTINED，不消费任务。
心跳与健康每 5s 上报 inFlight、成功率、P99、CPU、内存、连接池；连续 3 次丢失转 OFFLINE。停止分配；Kafka 未确认消息由其他消费者重取。
排空 Drain先停止拉取新消息，等待在途完成；默认 120s，超时取消请求并返回 EXECUTOR_DRAINED。发布升级、缩容和故障实例均走同一排空流程。
隔离 CordonSRE 可人工隔离异常实例或版本；支持按镜像版本批量隔离。隔离动作记录原因、操作者和恢复条件。
执行池管理按 PROD/NON_PROD、网络区、协议能力分池；配置 min/max replicas、单 Pod 吞吐和目标服务配额。无匹配池时任务进入 UNSCHEDULABLE，不跨环境兜底。
版本灰度新版本先 5% 实例，比较错误率/P99/资源；逐步 25%→50%→100%。指标超阈值自动隔离新版本并回滚。
状态机：STARTING → ONLINE → DRAINING → OFFLINE；任何状态可因身份、配置或行为异常进入 QUARANTINED。只有 ONLINE 实例加入 Consumer Group，DRAINING 只提交已领取任务的结果。
05 · AUTOSCALING & 10K TPS

自动扩缩容与 1W TPS 设计

扩缩容不能只看 CPU。HTTP Worker 是 I/O 密集型，核心信号应是任务到达率、Kafka Lag、最老消息年龄和在途请求数，CPU/内存作为安全补充。

基础副本：10,000 req/s ÷ 400 req/s/Pod = 25 Pods
冗余副本：ceil(25 × 1.30) = 33 Pods；峰值前预热 36 Pods
在途请求：10,000 × 0.2s 平均时延 = 2,000；3s 超时上界 = 30,000
单 Pod 上界：800 in-flight；36 Pods 总上界 28,800，超出时队列等待而非无限建连

128Kafka 分区 / 最大并行消费者基础

扩容策略

  • 每 5–10s 计算一次；到达率预测优先于 CPU。
  • 副本增长允许 100%/15s，发现 oldest message age > 5s 立即快扩。
  • 整点任务提前 2 分钟 scheduled scaling，避免冷启动追赶。
  • 保留 8 Pod 热池；镜像预拉取、连接池预热、readiness 通过后才消费。
  • 最大 80 Pod 不是越大越好，必须受目标服务、NAT、DNS、Kafka 和数据库容量约束。

缩容策略

  • 连续 10 分钟 lag=0、inFlight<30%、CPU<40% 才允许缩容。
  • 每 60s 最多缩 10%，避免流量波动导致抖动。
  • 缩容前将实例置为 DRAINING；在途归零或达到 120s 截止时间后退出。
  • 生产池永不缩到 0；分区拓扑需保证多可用区最小副本。
  • 缩容期间错误率上升或 lag 恢复，立即取消缩容。

端到端容量保护

层级设计1W TPS 下的保护
SchedulerElasticJob 分片；确定性 jitter；只生成轻量命令，不同步执行 HTTP。水平分片；批量读取配置；任务发布幂等。
KafkaCommand/Result 各 128 分区；按 environment+probePoint+targetHash 分区。削峰、背压、至少一次投递；单热点目标不会压垮全局。
Worker异步 HTTP Client、Keep-Alive、DNS 缓存、连接池、800 in-flight/Pod。全局/租户/目标三级令牌桶；目标并发上限优先。
ResultexecutionId 唯一；200–500 条或 100ms 微批写入；摘要与明细分离。避免 10k 单行事务/秒直接冲击 MySQL；Result Topic 可重放。
MySQL配置库与结果库隔离；执行表按日分区；短期明细 TTL；索引只覆盖常用查询。控制面不受结果洪峰影响；持续 10k/s 明细应迁移到列式/时序存储。
目标服务每 app/env/host 单独配置 QPS 与并发预算。全平台有能力发出 10k/s，不代表允许对单一服务发出 10k/s。

过载降级顺序

  1. 丢弃过期低优先级命令超过 deadline 的任务不补发陈旧流量，结果标记 EXPIRED。
  2. 降低非生产与低优先级频率PROD 核心探测优先，DEV/TEST 周期临时放大 2–5 倍。
  3. 关闭响应体断言和非必要采样保留状态码与时延，减少 CPU、内存和结果体积。
  4. 目标级熔断目标服务持续 429/503 或连接耗尽时停止加压，转为低频恢复探测。
  5. 全局保护Lag 持续恶化且达到 max replicas 时拒绝手动/临时任务，返回 503 + Retry-After。

07 · ACCEPTANCE

验收标准与压测方案

“支持 1W TPS”必须转化为可重复的验收场景，覆盖稳定吞吐、突发、扩容、故障恢复和目标保护，而不是只看某一秒的峰值数字。

功能验收

测试套 CRUD、版本发布、暂停恢复、Token 轮换吊销、执行机注册排空、容量策略修改均满足权限、幂等、状态机与审计要求。

稳态容量

在约定机器规格、平均响应 200ms 下持续 10,000 req/s 30 分钟；成功率 ≥99.9%，调度到结果 P99≤10s，Kafka oldest age≤5s。

突发与扩容

2,000→10,000 req/s 在 60s 内完成扩容并清空积压；无扩容抖动、无超最大副本、无目标级配额突破。

故障恢复

随机终止 30% Worker、单 AZ 故障、Kafka Consumer 重平衡时无结果丢失；重复结果由 executionId 幂等吸收。

安全验收

Token 不出现在页面响应、Kafka、日志和结果中；跨应用/环境使用被拒绝；SSRF、DNS 重绑定、保留地址访问均被阻断。

过载保护

目标服务返回 429/503、数据库变慢或达到 80 Pod 时，系统按优先级降级并拒绝临时流量，不拖垮控制面。

压测报告必填：Worker CPU/内存规格、Pod 数、Kafka 分区与 Broker、目标服务 Stub 延迟分布、连接复用率、持续时长、成功率、P50/P95/P99、Lag、最老消息年龄、结果入库延迟、错误分类和瓶颈结论。
